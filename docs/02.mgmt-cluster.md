# [Management Cluster](https://kamaji.clastix.io/getting-started/kamaji-kind/)

## Creating Kind Cluster
```bash
kind create cluster --image=artifactory.digikala.com/docker/kindest/node:v1.36.1 --name kamaji --config /opt/kind/kind-config.yaml
cat ~/.kube/config
```

## Installing Cert-Manager

```bash
cd ~/kaas

helm repo add jetstack https://charts.jetstack.io --force-update
helm repo update
helm pull jetstack/cert-manager --untar

helm upgrade --install cert-manager . -n cert-manager --create-namespace -f ./values-kaas.yaml
```

## Installing MetalLb
```bash
cd ~/kaas

helm repo add metallb https://metallb.github.io/metallb
helm repo update
helm pull metallb/metallb --untar

helm upgrade --install metallb . -n metallb-system --create-namespace -f ./values-kaas.yaml
```

## Creating IP Address Pool
Extract the Gateway IP of the network Kind is running on.
(This only works if Docker keeps IPv4 as index 1)

```bash
GW_IP=$(docker network inspect -f '{{(index .IPAM.Config 1).Gateway}}' kind)
NET_IP=$(echo ${GW_IP} | sed -E 's|^([0-9]+\.[0-9]+)\..*$|\1|g')

cat << EOF | sed -E "s|172.19|${NET_IP}|g" | kubectl apply -f -
apiVersion: metallb.io/v1beta1
kind: IPAddressPool
metadata:
  name: kind-ip-pool
  namespace: metallb-system
spec:
  addresses:
  - 172.19.255.200-172.19.255.250
---
apiVersion: metallb.io/v1beta1
kind: L2Advertisement
metadata:
  name: emtpy
  namespace: metallb-system
EOF
```

## Installing Kamaji
Kamaji requires a storage provider installed on the management cluster.

Kind by default provides local-path-provisioner, but one can have any other CSI Drivers.

```bash
cd ~/kaas

helm repo add clastix https://clastix.github.io/charts
helm repo update
helm search repo kamaji
helm pull clastix/kamaji --untar --version 0.0.0+latest

helm upgrade --install kamaji . -n kamaji --create-namespace -f ./values-kaas.yaml
```

Verify by first checking Kamaji CRDs
```bash
k get crds | grep -i kamaji
k get pod -n kamaji-system
```

## Creating Tenant Control Plane (for Test only)
Apply Tenant Cluster [sample](https://github.com/clastix/kamaji/tree/master/config/samples):

```bash
kubectl apply -f https://raw.githubusercontent.com/clastix/kamaji/master/config/samples/kamaji_v1alpha1_tenantcontrolplane.yaml
```
Check:
```bash
k get pod -n kamaji-system
    NAME                       READY   STATUS    RESTARTS   AGE
    k8s-130-6f49d94f4d-g6698   3/3     Running   0          3m21s

k get tcp -A
    NAMESPACE       NAME      VERSION   STATUS         CONTROL-PLANE ENDPOINT   KUBECONFIG                 DATASTORE   AGE
    kamaji-system   k8s-130   v1.30.0   Provisioning   172.18.255.200:6443      k8s-130-admin-kubeconfig   default     69s
```
Get kubeconfig:
```bash
SECRET=k8s-130-admin-kubeconfig
kubectl get secret $SECRET -n kamaji-system -o jsonpath='{.data.admin\.conf}'| base64 -d > /tmp/kamaji.conf
export KUBECONFIG=/tmp/kamaji.conf
# Notice that the kubectl version changes, and there are no nodes now.
kubectl version
kubectl get nodes
```

if it work now cleanup the tenant cluster
```bash
kubectl delete -f https://raw.githubusercontent.com/clastix/kamaji/master/config/samples/kamaji_v1alpha1_tenantcontrolplane.yaml
```
